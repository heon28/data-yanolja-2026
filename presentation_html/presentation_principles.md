# Presentation Principles

이 문서는 새 HTML 발표에 적용할 말하기 원칙입니다.
기반 분석은 `../docs/how_to_speak/patrick_winston_analysis.md`를 참고합니다.

## 1. 현재 상태

- 기존 PPT와 기존 HTML 초안은 참고하지 않는다.
- 새 발표는 `presentation_html/` 아래 HTML 파일로 다시 작성한다.
- Pretendard 폰트는 `../fonts/Pretendard-1.3.9/`에서 로드한다.
- 최종 스크립트는 인터뷰 이후 작성한다.

## 2. 발표의 잠정 중심

아직 인터뷰 전이므로 최종 문장으로 확정하지 않는다.
현재까지의 작업 가설은 다음이다.

> A/B 테스트는 좋은 비교 도구다.
> 하지만 후보를 어떻게 고를지부터 문제라면,
> 실험 문제를 `objective`, `constraint`, `context`로 다시 정의해야 한다.

이 문장은 인터뷰를 거쳐 바뀔 수 있다.

## 3. Winston식 구조 적용안

### 3.1 Empowerment promise로 시작한다

첫 장은 주제 소개가 아니라 청중에게 줄 능력의 약속이어야 한다.

잠정 약속:

> 오늘 발표가 끝나면, 여러분은 A/B 테스트 이후의 실험 문제를
> `objective`, `constraint`, `context`라는 세 단어로 다시 정의할 수 있게 됩니다.

### 3.2 초반에 울타리를 친다

오해를 막기 위해 발표 초반에 "이 발표가 아닌 것"을 명확히 한다.

- A/B 테스트 폐기론이 아니다.
- 예측 모델 튜토리얼이 아니다.
- Ax / BoTorch API 강의가 아니다.
- 연령/성별이 고객 반응을 본질적으로 결정한다는 주장이 아니다.

### 3.3 하나의 질문을 반복해서 순환한다

반복할 중심 질문 후보:

> 다음 실험은 어디에 찍어야 할까?

이 질문은 매번 다른 수준으로 돌아와야 한다.

- 비교 후보가 둘이 아닐 때
- `x* = argmax_x f(x)`를 설명할 때
- uncertainty와 acquisition을 설명할 때
- CRM 정책 heatmap을 볼 때
- opt-out constraint가 해를 바꿀 때
- context별 최적 정책을 볼 때

### 3.4 Verbal punctuation을 명시한다

청중이 놓쳐도 복귀할 수 있도록 전환 문장을 둔다.

- "첫 번째 전환입니다. 비교에서 탐색으로 갑니다."
- "두 번째 전환입니다. 매출 최대화에서 운영 가능한 해로 갑니다."
- "세 번째 전환입니다. 전체 평균에서 context별 정책으로 갑니다."

### 3.5 질문과 침묵을 설계한다

질문은 슬라이드에 답을 먼저 보여주지 않는다.
질문 뒤에는 실제 발표자가 멈출 수 있어야 한다.

질문 후보:

- "할인율이 0%, 10%, 20%, 30%라면 네 개를 다 A/B 테스트하면 끝일까요?"
- "수익이 제일 높은 정책이 opt-out도 제일 높다면, 그 정책은 좋은 정책일까요?"
- "모든 고객군에 같은 발송 시점이 최적일까요?"

### 3.6 슬라이드는 대본이 아니라 조미료다

HTML 슬라이드는 발표자가 읽을 문서가 아니다.

- 한 슬라이드에는 큰 한 문장만 둔다.
- 수식은 한 장에 하나만 둔다.
- 그림은 한 메시지만 설명해야 한다.
- 긴 설명은 speaker script에만 둔다.
- 글자가 많아지는 순간 Winston의 원칙을 위반한 것으로 본다.

### 3.7 기억 장치를 의도적으로 만든다

Winston의 symbol, slogan, surprise, salient idea, story를 이 발표에 맞게 설계한다.

- Symbol 후보: `discount_rate x send_timing` 위의 feasible policy map
- Slogan 후보: "다음 실험을 더 똑똑하게 찍는다"
- Surprise 후보: "최고 수익점이 최적 정책이 아닐 수 있다"
- Salient idea 후보: `objective`, `constraint`, `context`
- Story 후보: CRM 쿠폰 발송 정책을 적은 실험으로 찾아가는 이야기

이 요소들은 인터뷰에서 확정한다.

### 3.8 마지막은 contribution으로 끝낸다

마지막 슬라이드는 `Thank you`가 아니라 발표가 남긴 것을 보여줘야 한다.

Contribution 후보:

1. A/B 테스트 이후의 문제를 정책 탐색으로 보는 언어
2. 제약 있는 feasible optimum이라는 실무적 기준
3. context별 최적화와 정보 공유라는 확장 방향

마지막 말 후보:

> 다음 실험을 설계할 때 A와 B를 고르기 전에, 먼저 세 줄을 적어보세요.
> Objective. Constraint. Context.
> 그 세 줄이 정리되면, 이미 더 나은 실험을 시작한 것입니다.

## 4. 인터뷰 후 확정할 항목

스크립트 작성 전 아래 항목을 사용자와 확인한다.

- 청중의 실제 구성과 기대 수준
- 발표자가 반드시 말하고 싶은 개인 경험
- CRM 예제의 현실감 수준
- 수식과 기술 설명의 깊이
- A/B 테스트에 대한 비판 수위
- Ax / BoTorch를 보여줄 필요와 깊이
- constraint의 최종 표현
- context 예시의 적절성
- 발표의 마지막 행동 요청
